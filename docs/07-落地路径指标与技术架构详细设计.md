# 07 · 落地路径、指标与技术架构详细设计

> 本章把前 6 章串成可执行的实施蓝图：分阶段路径（先后与依赖，不谈日历周期）、系统架构、指标体系与避坑清单。

---

## 1. 系统架构概览

```
┌──────────────────────────────────────────────────────────┐
│                     接入层 / 触达通道                       │
│   App · 站内IM · 微信卡片 · 短信 · 虚拟号网关(隐私号)        │
└───────────────┬──────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────┐
│                     业务能力层（AI 服务）                   │
│  撮合引擎 · 线索评分 · 触发器引擎 · AI销售副驾驶            │
│  建议报价 · 锁价 · 账期撮合 · 信用风控 · 弃单挽回           │
└───────────────┬──────────────────────────────────────────┘
                │  所有数据访问经过 →
┌───────────────▼──────────────────────────────────────────┐
│              权限/归属网关（防撬客核心闸门）                │
│   归属判定 · 可见性过滤 · 撞单仲裁 · 审计日志              │
└───────────────┬──────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────┐
│                       数据底座                              │
│  客户360 · 事件流 · 供需意图 · 意图标签 · 信用档案         │
│  联系方式保险库(KMS加密) · 公域/私域池                     │
└──────────────────────────────────────────────────────────┘
```
**关键设计**：业务能力层不能直连数据库，必须穿过"权限/归属网关"。这是"绝不撬客"在架构上的物理保证。

## 2. 分阶段落地路径（先后与依赖）

| 阶段 | 交付内容 | 依赖 | 价值 |
|---|---|---|---|
| 阶段一 数据与信任地基 | 客户360 + 事件流 + 归属层 + 私域/公域池 + 权限网关 + 联系方式托管 | 无（最先做） | 让商家敢放真实客户进来；所有 AI 的前提 |
| 阶段二 智能获客 | 公域供需撮合 + 线索评分 + 行情钩子 | 阶段一 | 最快见效、零边际成本拉新激活 |
| 阶段三 智能运营 | 客户分层 + 触发器引擎（补货/价格异动）+ AI 销售副驾驶 | 阶段一标签 | 提复购、养熟、放大业务员产能 |
| 阶段四 智能转化与风控 | 建议报价 + 锁价 + 账期撮合 + 信用评分 + 弃单挽回 | 阶段一交易/回款数据 | 提成交、控坏账、差异化壁垒 |
| 阶段五 模型化升级 | 撮合排序模型 + 信用模型 + 复购预测 + 审计透明看板完善 | 阶段二~四数据沉淀 | 从规则驱动升级到模型驱动 |

> 依赖主线：一切依赖阶段一的数据质量与归属机制；信用/风控依赖回款历史，先规则后模型。

## 3. 指标体系（北极星 + 分层）

### 3.1 北极星指标
**平台撮合促成的有效成交额（GMV）** + **商家真实客户录入率**（信任度的代理指标）。

### 3.2 分层指标
| 域 | 指标 |
|---|---|
| 获客 | 撮合点击率、询价转化率、线索→注册→首单转化率、行情卡片带新客数 |
| 运营 | 复购率、月活、沉睡唤醒率、AI 触达打开/回应率、业务员人均有效跟进数 |
| 转化 | 询价→成交转化率、平均成交时长、锁价订单占比、弃单挽回率 |
| 风控 | 赊销坏账率、回款及时率、信用模型准确率 |
| 信任 | 真实客户录入率、私域客户占比、客户主权投诉率（↓）、审计看板使用率 |

### 3.3 指标看板
- 商家侧：自己的获客/运营/转化效果 + 客户被访问审计。
- 平台侧：全局供需热度、撮合效率、风控水位、信任指标趋势。

## 4. 关键技术选型建议（方向性）
- **事件流**：消息队列 + 流处理，支撑高频埋点与准实时画像。
- **规则引擎**：可配置规则（保护期、触发器、仲裁优先级），运营可调参不改码。
- **特征/标签**：离线批 + 实时特征结合；标签带置信度。
- **模型服务**：撮合排序（LTR）、信用评分（GBDT 起步）、复购预测；统一模型服务网关。
- **隐私**：KMS 加密联系方式、隐私号网关、行级权限中间件、全链路审计。

---

## 5. 风险与避坑清单
1. **不先投广告**：先盘活平台内已有供需数据，ROI 更高。
2. **触达去微信/短信/电话**，别只在 App 推。
3. **信用风控是壁垒**：纯撮合易被线下绕过，"管住账期和坏账"让客户离不开。
4. **AI 给建议、人做决策**：涉及金额/账期的环节必须人工确认。
5. **冷启动用规则先跑**，数据足够再上模型。
6. **客户主权先做实**：归属机制和数据隔离不到位，商家不会放真实客户进来，后续全盘落空。
7. **撮合严守公域边界**：任何一次"把私域客户撮合给别人"的事故都会摧毁信任，宁可保守。
8. **触达频控**：跨触发器统一频控，避免骚扰导致客户反感与退订。

---

## 6. 验收标准（每阶段 Done 的定义）
- 阶段一：任意接口都无法越权读取他人私域/战略客户；联系方式全程脱敏；归属变更可审计。
- 阶段二：公域撮合可跑通"挂货→匹配→推送→询价"，且校验过绝不命中私域。
- 阶段三：补货/价格异动触发器自动运行且受频控；AI 简报与话术可用。
- 阶段四：建议报价/锁价/账期/信用拦截/弃单挽回链路打通；坏账可控。
- 阶段五：模型上线且效果优于规则基线；商家透明看板可自助查询。
