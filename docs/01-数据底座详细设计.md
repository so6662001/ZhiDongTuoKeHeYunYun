# 01 · 数据底座详细设计（客户 360 + 意图标签 + 归属层）

> 数据底座是全案地基，所有 AI 能力（撮合、评分、提醒、风控）都依赖它。本章给出可直接转成数据库表的字段设计、打标签规则与数据治理方案。

---

## 1. 设计原则

1. **统一主键**：企业、用户（联系人）、客户关系三者分离建模，避免"一个企业多个账号"导致数据割裂。
2. **事件驱动**：所有交互（浏览/询价/报价/成交/聊天）以事件流落库，再聚合成画像，保证可追溯、可重算。
3. **隐私与归属优先**：每条客户数据都带"归属商家"和"可见性"标记，未授权方查询不到（详见 02 章）。
4. **冷启动友好**：画像字段允许大量为空，标签随数据积累逐步丰富；先规则后模型。

---

## 2. 核心实体与关系（ER 概览）

```
企业 Enterprise 1 ──< 联系人 Contact
企业 Enterprise 1 ──< 库存/货源 Listing（卖方）
企业 Enterprise 1 ──< 求购意图 Demand（买方）
商家 Merchant   1 ──< 客户关系 CustomerRelation >── 1 企业(作为客户)
事件 Event       >── 关联 企业/联系人/Listing/Demand
成交 Deal        >── 买方企业 + 卖方商家 + 品种规格
信用档案 CreditProfile 1 ── 1 企业
```

- **Merchant**（商家）：平台的付费经营者（生产企业/批发商/贸易公司/门零），是"客户的拥有方"。
- **Enterprise**（企业）：产业链上的任一主体，可同时是某商家的"客户"，也可能自己是商家。
- **CustomerRelation**：商家与其客户之间的归属关系，是防撬客的核心载体（详见 02 章）。

## 3. 字段设计（可直接建表）

### 3.1 企业身份层 `enterprise`
| 字段 | 类型 | 说明 |
|---|---|---|
| enterprise_id | bigint PK | 企业唯一 ID |
| name | varchar | 企业名称 |
| ent_type | enum | 生产/批发/贸易/门零/终端 |
| scale | enum | 规模分档：大/中/小/微 |
| region_code | varchar | 所在区域（省/市/区） |
| main_categories | json | 主营品种数组：螺纹/线材/盘螺/热卷/冷卷/中厚板/型钢… |
| qualification | json | 资质信息（营业执照、一般/小规模纳税人等） |
| credit_score | int | 信用分（0-100，来自 CreditProfile，详见 05 章） |
| created_at / updated_at | datetime | 时间戳 |

### 3.2 联系人层 `contact`
| 字段 | 类型 | 说明 |
|---|---|---|
| contact_id | bigint PK | 联系人 ID |
| enterprise_id | bigint FK | 所属企业 |
| name | varchar | 姓名 |
| role | enum | 老板/采购/销售/财务/仓管 |
| phone_token | varchar | **脱敏托管的电话**（虚拟号映射，详见 06 章） |
| wechat_bound | bool | 是否绑定微信触达通道 |
| is_decision_maker | bool | 是否决策人 |

### 3.3 行为事件层 `event`（事件流，高频写入）
| 字段 | 类型 | 说明 |
|---|---|---|
| event_id | bigint PK | 事件 ID |
| enterprise_id | bigint | 行为主体企业 |
| contact_id | bigint | 触发联系人 |
| event_type | enum | view/search/inquiry/quote/visit/order/abandon/chat/share |
| category | varchar | 品种 |
| spec | varchar | 规格（如 HRB400E Φ20） |
| quantity | decimal | 数量（吨） |
| price | decimal | 涉及价格 |
| direction | enum | buy/sell |
| region_code | varchar | 相关区域 |
| keywords | json | 聊天/搜索关键词抽取 |
| occurred_at | datetime | 发生时间 |

### 3.4 供需意图层（最值钱）
**货源 `listing`（卖方挂货）**
| 字段 | 类型 | 说明 |
|---|---|---|
| listing_id | bigint PK | 货源 ID |
| merchant_id | bigint | 挂货商家 |
| category / spec | varchar | 品种 / 规格 |
| quantity | decimal | 可售吨位 |
| price / price_type | decimal/enum | 价格 / 一口价或可议 |
| warehouse_region | varchar | 货物所在仓库区域 |
| account_period_days | int | 可接受账期 |
| visibility | enum | private/assigned/public（详见 02 章） |
| status | enum | 在售/锁定/已售/下架 |

**求购意图 `demand`（买方需求）**
| 字段 | 类型 | 说明 |
|---|---|---|
| demand_id | bigint PK | 需求 ID |
| enterprise_id | bigint | 求购企业 |
| category / spec | varchar | 品种 / 规格 |
| quantity | decimal | 需求吨位 |
| target_price | decimal | 心理价位（可空） |
| delivery_region | varchar | 收货区域 |
| urgency | enum | 急/一般/观望 |
| is_public | bool | 是否愿意公开被多家报价 |
| valid_until | datetime | 有效期 |

### 3.5 归属层 `customer_relation`（防撬客核心，详见 02 章）
| 字段 | 类型 | 说明 |
|---|---|---|
| relation_id | bigint PK | 关系 ID |
| merchant_id | bigint | 归属商家 |
| customer_enterprise_id | bigint | 客户企业 |
| relation_type | enum | imported/invited/dealt/claimed |
| is_strategic | bool | 是否战略（高价值）客户，永不入公海 |
| protect_until | datetime | 保护期截止时间 |
| visibility | enum | private/assigned/public |
| status | enum | active/expired/returned_to_pool |

## 4. 意图标签体系（画像的灵魂）

由 `event` + `deal` 聚合计算，定期刷新。

| 标签类 | 示例标签 | 计算逻辑 |
|---|---|---|
| 供需方向 | 长期求购 HRB400E Φ20 | 近 90 天该规格 inquiry/search ≥ 3 次且无对应 sell |
| 出货意图 | 持续出货热卷 | 近 90 天 listing(sell) 该品种 ≥ N 次 |
| 复购周期 | 螺纹复购周期 ≈ 18 天 | 历史成交时间间隔中位数 |
| 价格敏感度 | 高/中/低 | 弃单与价格波动相关性 |
| 区域偏好 | 偏好华北仓 | 成交/询价的 region 分布 |
| 活跃度 | 活跃/沉睡/流失风险 | 最近活跃时间 + 频次衰减 |
| 价值分层 | 高/中/低价值 | 成交额 × 频次 × 毛利 × 回款表现 |

> 标签同时写入"置信度"，冷启动期低置信标签仅用于参考、不触发自动动作。

## 5. 数据采集与治理

1. **采集来源**：平台内行为埋点、询报价/找货模块、IM 聊天（NLP 抽取意图）、成交与回款记录、商家手工录入/导入。
2. **打标签管线**：事件流 → 实时/准实时聚合 → 画像表 → 标签计算 → 供下游消费。
3. **数据质量**：对手工录入做查重（企业名称/电话归一）、对异常值（价格、吨位离群）做校验。
4. **权限与隔离**：所有查询经过"归属 + 可见性"过滤（详见 02 章）；AI 训练用聚合/匿名数据，禁止反推到具体商家的具体客户。
5. **可重算**：画像与标签可由事件流全量重算，便于规则迭代与纠错。

---

## 6. 冷启动策略

| 阶段 | 数据情况 | 做法 |
|---|---|---|
| 启动期 | 几乎无交易数据 | 用企业类型+品种+区域做粗规则匹配；引导商家导入存量客户 |
| 成长期 | 有一定行为/询价 | 启用意图标签，规则驱动撮合与提醒 |
| 成熟期 | 充足成交+回款 | 上模型：撮合排序、信用评分、复购预测 |

---

## 7. 输出给下游的关键数据接口（草图）

- `GET /profile/enterprise/{id}` → 客户 360 视图（受权限过滤）
- `GET /intent/demands?category=&spec=&region=&scope=public` → 公域求购意图（供撮合）
- `GET /intent/listings?...&scope=public` → 公域货源
- `GET /tags/enterprise/{id}` → 意图标签集合
- 事件写入：`POST /events`（统一事件入口）
