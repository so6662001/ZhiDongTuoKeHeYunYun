# 05 · 智能转化与信用风控详细设计

> 钢铁转化不是"加购下单"，而是 **问价 → 锁价 → 打款 → 提货** 全链，且必须管控信用/账期风险。本章覆盖建议报价、锁价、账期撮合、信用评分、弃单挽回。

---

## 1. 转化链路与状态机

```
询价 inquiry ─▶ 报价 quote ─▶ 锁价 lock ─▶ 下单 order ─▶ 打款 pay ─▶ 提货 deliver ─▶ 完成/回款
      │             │            │           │           │
   弃单挽回      重新报价      锁价到期     取消订单     风控拦截
```
每个节点都有 AI 辅助与风控校验。

---

## 2. 智能建议报价

### 2.1 给卖方的"建议报价区间"
买方发起询价时，向卖方生成 `suggested_price_range`：
```
suggested = f(
    market_ref_price,        // 平台成交均价 + 公开行情
    listing_cost_or_floor,   // 卖方成本/底价（私密，仅卖方可见）
    inventory_age,           // 库龄越长越倾向降价走量
    buyer_credit_tier,       // 买方信用越好可越优惠
    deal_history,            // 双方历史成交价
    urgency                  // 紧迫度
)
返回: { low, mid, high, rationale }
```
- 仅给卖方看（含底价逻辑），保护卖方定价隐私。
- 附"理由"：如"低于近 7 天均价 1.5%，库龄 25 天建议走量"。

### 2.2 给买方的"价格参考与锁价提示"
- 买方端展示"该报价 vs 近 7 天市场均价"的相对位置（不泄露卖方底价）。
- 当报价低于均价阈值时提示："当前价处于近期低位，建议锁价。"

## 3. 智能锁价

钢价波动大，锁价降低双方决策犹豫、加速成交。

| 要素 | 设计 |
|---|---|
| 锁价时长 | 可选（如 2h / 6h / 24h），波动越大时长越短 |
| 锁价保证金 | 按吨位与时长收取小额保证金，防恶意占价 |
| 风险对冲 | 平台对锁价敞口做风控限额；剧烈行情可缩短/暂停锁价 |
| 到期处理 | 到期未下单则释放，价格回到实时；可一键续锁 |

**场景**：
> 买方询价得报价 X，AI 提示"低于近 7 天均价" → 买方选择锁价 6 小时（付小额保证金） → 6 小时内完成下单打款 → 锁价生效成交。

## 4. 账期撮合（转化杠杆 + 风险控制）

### 4.1 AI 推荐可给账期
基于买方信用评分，向卖方推荐"可安全给出的账期"：
```
recommended_terms = g(credit_score, history_repayment, order_amount, relationship)
返回: { account_period_days, credit_limit, require_prepay_ratio }
```
- 高信用买方 → 建议给账期（如 7/15 天），提升成交率。
- 低信用买方 → 建议预付比例或拒绝赊销。

### 4.2 与金融服务联动（可选增值）
- 对接供应链金融/账期保理，平台做撮合方而非资金方（控风险）。

## 5. 信用评分体系

### 5.1 评分输入
| 维度 | 信号 |
|---|---|
| 历史回款 | 账期回款及时率、逾期次数与天数 |
| 交易行为 | 成交频次、履约率（下单后实际提货比例）、取消率 |
| 企业资质 | 经营年限、规模、资质完整度 |
| 外部数据（可选） | 工商风险、司法涉诉、舆情（合规获取） |

### 5.2 评分输出与应用
```
credit_score ∈ [0,100]  → 信用等级 A/B/C/D
A: 可给较长账期 + 高额度
B: 可给短账期 + 中额度
C: 预付为主 + 低额度
D: 仅现款现货 / 限制交易
```
- 评分写回 `enterprise.credit_score`，供撮合排序、账期推荐、风控拦截统一使用。
- 冷启动用规则与资质打底，积累回款数据后上模型。

### 5.3 风控拦截点
- 下单/账期申请时校验信用等级与额度，超限拦截或转人工。
- 异常行为（短期大量占价、频繁取消）触发风控审查。

## 6. 弃单挽回

### 6.1 卡点识别
对"询价后 N 小时未成交"或"下单后未打款"的单子，AI 推断卡点：
| 卡点信号 | 判断依据 | 挽回动作 |
|---|---|---|
| 嫌价高 | 报价高于其历史成交价/市场价 | 卖方让利提示 / 推平价替代货源 |
| 账期不满意 | 曾申请更长账期 | 在信用允许内放宽账期 |
| 物流成本 | 收货地远 | 提供含运报价 / 就近货源 |
| 单纯观望 | 价格敏感度高 + 行情震荡 | 锁价提示 / 低点提醒 |

### 6.2 挽回流程
```
弃单/未打款 → AI 判断卡点 → 生成针对性挽回方案 → 通知卖方/业务员确认 → 触达买方 → 二次转化
```
涉及让利、账期的方案需卖方/业务员确认（人机协作边界，与 04 章一致）。

---

## 7. 与归属机制的衔接
- 转化全程在归属商家与其客户之间进行；公域撮合促成的首单成交后，按 02 章自动建立归属关系并起算保护期。
- 建议报价的底价、信用评分的明细等敏感数据严格按可见性隔离（详见 06 章）。

---

## 8. 关键指标
- 询价→成交转化率、平均成交时长、锁价订单占比、锁价成交率。
- 账期订单坏账率、回款及时率。
- 弃单挽回率、挽回带来的成交额。
- 信用模型 AUC / 逾期预测准确率（成熟期）。
